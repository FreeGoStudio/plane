# 需求文档审查阻断规则

依据：用户于 2026-11-25 确认实施审查 Agent 优化方案，包括分级与阻断分离、六项举证、等效覆盖、不确定事项处理、最小修复和复审边界。

## 实现入口

- `apps/api/plane/singularity/requirement_review_policy.py`：模型规则、结构化举证、阻断一致性校验及详情文本。
- `apps/api/plane/singularity/requirement_review_generation.py`：新生成结果必须包含 policy；历史结果允许缺省，原报告不重写、不自动重新审查。

P0/P1 只有符合举证条件才阻断；P2/P3 不阻断。已证实阻断映射为 `blocking`；待澄清或待验证事项仅在涉及原定交付必要前置条件时映射为 `missing_information`，否则为 `suggestion`。沿用原有报告 verdict 及固定版本采用门禁。

每个新问题保留等级、证据状态、阻断范围、原始依据和来源、缺口、反例、影响、等效覆盖检查、最小修复及关闭条件。字段同时保存在 policy 中并展示于现有 reason 详情，兼容现有 API/MCP 与页面消费者，无数据库迁移。

服务端校验原始引文存在于固定快照、必要举证非空、等级/覆盖/证据状态与阻断分类一致，以及原有文件位置、引文和 verdict 约束。违反约束的输出进入现有失败重试流程，不能静默转为通过。

原始来源是否确为已确认要求、反例逻辑是否成立及覆盖是否语义等价仍由模型依据固定输入判断；字段校验不等于证明其业务结论正确。阻断范围描述受影响验收单元，当前采用操作仍针对整个固定文档版本，不新增部分版本合并或自动修复授权。

## 验证与发布边界

单元测试 `plane/tests/unit/test_requirement_review_policy.py` 覆盖 P0/P1 举证、P2/P3 不阻断、等效覆盖、六项举证缺失、非前置条件缺证不阻断、前置条件待验证、原始引文校验、历史报告、零问题通过、原有证据/结论校验，以及模型响应到现有详情的完整转换（模拟模型响应）。

此变更为源码实现，不代表已部署或真实模型业务验收通过。部署后仅新执行的审查使用新规则；历史报告保持原结论，重新审查需按既有显式流程发起。
