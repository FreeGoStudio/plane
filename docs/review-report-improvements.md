# 需求与代码审查报告改进

用户依据：2026-11-25 对审查报告难读的反馈、CodeRabbit 对比及“实现改进建议”。本次验收单元是报告阅读与复审追溯，不扩展需求范围、自动修复、业务验收或人工放行权限。

| 验收点               | 原有缺口                           | 实现                                                                                  |
| -------------------- | ---------------------------------- | ------------------------------------------------------------------------------------- |
| 先看到结论和下一步   | 版本元数据挤占首屏，结论与细节混排 | 共用总览、数量、下一步；元数据折叠；长检查说明展开阅读                                |
| 知道检查了什么       | 只有问题列表，不能区分通过与未检查 | 需求四项文档检查，代码覆盖/问题/运行测试/需求符合性分别显示；后两项明确未检查         |
| 需求覆盖可追溯       | 未逐项关联原始要求与文档证据       | 从固定原始正文提取陈述清单，模型逐项给出状态，后端验证完整性、引用与关联问题          |
| 代码改动易定位       | 文件覆盖清单与问题难关联           | 文件目录分组、问题计数、保留工具实际摘要；无摘要时只展示事实统计                      |
| 问题可定位和交接     | 路径不可直接打开，缺少修复交接     | 固定 SHA 源码链接、复制最小修复上下文；复制不执行修复                                 |
| 复审变化可信         | 只能逐轮手动对照                   | 同一路径及断言精确匹配，标注新增/仍观察到/本轮未观察到；不推定已修复                  |
| 已完成报告可重新审查 | 失败重试无法用于已完成评审         | 同一未采用版本的显式复审，幂等请求，保留旧记录；旧结论失效，采用中/已采用版本禁止重审 |

需求覆盖只证明文档覆盖，不证明程序实现。原始正文中的背景可明确标记不适用，但不能遗漏；无法判断应标记待核对或未检查。覆盖矩阵、检查项及策略版本只对新报告生成，旧报告显示缺失提示，不伪造通过结果。

问题对比使用精确断言；模型改写表达可能形成一项新增和一项未再次观察到，不能作为真实修复统计。同 SHA 的报告差异明确提示不能归因于文档/代码修改。代码分组以目录为粒度，不声称提供模型未生成的逐组业务变更解释。

验证：111 项需求/代码审查后端回归通过；补充摘要字符串与被替代报告接口断言后定向复验。19 项前端交互测试通过；Web 类型、Ruff、OxLint 通过。新增 52 项标签在 22 种语言同步，中英文已提供，其余使用英文占位；全局既有其他语言各 1,277 项缺失不属于本次改动。本地注释检查完成，PR 覆盖率待验证。

部署与真实浏览器证据保存在独立 plane-ops 仓库；最终视觉签收及真实业务重新验收需分别记录，不能用合成测试替代。
