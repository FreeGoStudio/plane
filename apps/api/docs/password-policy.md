# 密码规则（NIST SP 800-63B-4）

需求来源：用户要求移除字符组成强制规则，并继续调整其余密码规则，包括单因素最低 15 位；验证后本地提交。

## 实现与验收范围

- 注册（Web / Space）、管理员初始化、设置、修改、重置及命令行重置密码统一要求至少 15 个 NFC 归一化后的 Unicode 码点。当前密码可单独用于登录，因此不采用仅限 MFA 密码的 8 位例外。
- 不要求大小写、数字或特殊字符组合；不再将 zxcvbn 评分作为准入条件。整个密码与阻止名单匹配，不检查密码中的单词或子串。
- 使用现有 Django 常见密码词表和 zxcvbn 的 passwords 泄露密码频率词表；依赖版本由 uv.lock 固定。账号邮箱和用户名也按整个值匹配。检查完全在本地进行，不传出密码。
- 支持空格、Unicode 和超过 64 字符的密码；不截断验证或存储。前端密码输入允许自动填充、粘贴和显示密码。
- 区分长度不足与阻止名单拒绝原因，并提示选择不同的长密码短语。
- 未发现定期强制换密的执行逻辑，也没有新增此类规则。原有登录节流与加盐哈希继续保留。

## 兼容与部署

新哈希使用 pbkdf2_sha256_nfc 算法标识，继承 Django PBKDF2 的盐与工作因子；保留 Django 原有算法用于验证历史哈希。已有短密码不会仅因本次策略改变而被强制重置；旧账号成功登录后由 Django 升级哈希。

部署时所有 API/worker 实例必须使用包含该 hasher 的版本。开始写入新哈希后，不可直接回退到无法识别 pbkdf2_sha256_nfc 的旧代码；回退版本仍须保留该 hasher。

阻止名单是依赖自带的有限、静态语料，并非实时查询全部泄露库；后续依赖维护时应复核词表覆盖。这次不新增账号泄露检测服务，已确认账号泄露后的运营处置仍需单独执行。HTTPS、生产部署配置及完整身份认证保证等级不属于此次代码验证的合规认证。

## 验证

- 自动测试覆盖 14/15 字符边界、Unicode 码点与 NFC、单一字符类型、空格、64/320 字符不截断、已泄露整串与子串区别、账号整串、旧哈希与旧短密码登录。
- 集成测试覆盖 Web / Space 注册与重置、设置及修改、管理员初始化、命令行重置。
- 前端组件测试覆盖密码提示、自动填充、粘贴、显示密码；共享包构建、类型检查及格式/lint 验证。
- 自动验证结果：100 项后端测试、16 项前端测试通过；Web / Admin / Space 及 utils / constants / blocks 类型检查通过，相关构建与 Python lint 通过。
- 实现及自动验证完成；未部署，生产最终验收待部署后完成。
